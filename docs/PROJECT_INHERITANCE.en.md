# Project Inheritance

Chinese version: [PROJECT_INHERITANCE.md](./PROJECT_INHERITANCE.md)

`pantheon-ops` inherits through a complete Pantheon Base snapshot plus a declarative business overlay. An upgrade rebuilds the product tree from a selected Base commit and injects Ops-owned business assets. It does not patch an old tree file by file or maintain shared-source allowlists.

## Ownership

- `pantheon-base` owns `platform`, `system/*`, shared backend/frontend, generators, and product engineering configuration.
- `pantheon-ops` owns `business/bizscope`, `business/cmdb`, `business/deploy`, business smoke, business design, and repository identity.
- `business-overlay.json` is the only machine-readable asset and assembly manifest.
- `.business-overlay-report.json` records the Base commit, Ops file hashes, generated files, and import rewrites.

The rebuilt tree keeps the Base layout and Go module identity `pantheon-base`. Injected business imports are rewritten from the historical `pantheon-ops/backend/...` prefix to `pantheon-base/...`; shared source is never rewritten to an Ops module identity.

## Assembly Points

Business modules attach through static overlay registries generated by the Ops rebuilder:

- `backend/modules/business/business_overlay_registry.go`
- `frontend/src/modules/businessOverlay.ts`
- `frontend/src/core/router/businessOverlayComponentRegistry.ts`
- `backend/modules/system/iam/menu/business_overlay_component_registry.go`

The rebuilder wires these static registries into Base aggregation points. Base `generated_*` registries remain exclusively owned by the low-code generator and may be regenerated or purged without carrying built-in Ops registrations. Each business module owns its migrations, menu and permission seeds, runtime i18n seeds, and API routes.

Base's menu-contract gate (`check-menu-contract.mjs`) discovers component registry files by name convention (frontend `*Registry.ts`, backend `*registry.go`), so `businessOverlayComponentRegistry.ts` / `business_overlay_component_registry.go` are automatically included in the consistency check without registering a file list on the base side.

## Upgrade

```powershell
npm run rebuild:from-base -- --base ..\pantheon-base --target .tmp\clean-base-overlay
node scripts/business-overlay/check-business-overlay.mjs --root .tmp\clean-base-overlay
```

Run backend, frontend, business smoke, and SonarCloud gates in the staged tree. Replace the current Ops baseline only after they pass. Identical Base and overlay inputs must produce identical output. The weekly workflow rebuilds against Base HEAD and reports real contract breaks instead of source drift.

## Prohibited

- Do not publish Base patches merely to extend a consumer allowlist.
- Do not copy Base release-producer tooling into Ops.
- Do not rewrite the complete Base tree to a `pantheon-ops` Go module.
- Do not retain generic product files absent from `business-overlay.json`.
- Do not replace the current Ops tree before staged verification.

This baseline replacement is an L2 human gate. Required validation includes overlay tests/checks, Windows Go race with CGO, frontend lint/type/build, business smoke, and SonarCloud revision/size/duplication review.
