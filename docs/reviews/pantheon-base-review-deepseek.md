## 1. 项目概览

Pantheon-Base 是一个面向企业后台的**模块化单体（Modular Monolith）**底座平台，核心设计理念包括：

- 可持续演进
- 系统域与业务域解耦
- AI 友好的后台基础设施

产品路线图规划 V1.0 里程碑于 2026‑07‑21 发布，当前为 v0.11.1 迭代版本。

**核心能力矩阵**：

| 能力域 | 具体功能 |
|--------|----------|
| 认证与会话 | Access Token + Refresh Token 双令牌机制 |
| 权限管理 | Casbin 策略引擎（页面权限 + 操作权限） |
| 组织管理 | 组织架构、用户、角色 |
| 配置治理 | 动态配置、敏感密钥保护 |
| 审计日志 | 登录日志、操作日志、安全事件 |
| 动态菜单 | 基于权限的动态渲染 |
| 低代码生成 | 受控代码生成（非运行时）与模块治理 |

## 2. 架构与技术栈

### 2.1 总体架构

项目采用 **三层分离** 架构设计：

| 层级 | 职责 |
|------|------|
| **平台层** | 应用壳、路由装配、中间件、工作台、跨域聚合视图 |
| **系统域** | 认证安全、用户角色权限、菜单、组织、配置、字典、审计等底座能力 |
| **业务域** | 通过 `modules/business/*` 和前端 manifest 注册，不直接依赖系统域内部实现 |

该分层符合**领域驱动设计（DDD）**思想，系统域与业务域解耦为长期演进奠定了良好基础。

## 4. 安全性

### 4.1 认证与授权

- **双 Token 机制**：Access Token（短期）+ Refresh Token（长期）
- **密钥强度**：所有 Secret 至少 32 字节
- **权限模型**：Casbin 策略支持页面级 + 操作级权限
- **会话管理**：在线会话、登录日志、注销失效
- **敏感配置**：`PANTHEON_SETTING_SECRET` 加密存储

### 4.2 安全运维配置

- 生产环境**禁止** GORM AutoMigrate
- 密钥通过集群 Secret、Vault 或等价系统注入，禁止提交 `.env` 文件
- CORS 需明确配置 `PANTHEON_ALLOWED_ORIGINS`（生产前端 origin）
- 初始管理员密码强制至少 12 位
- Docker 最终进程以非 root 用户运行

### 4.3 待完善的安全能力

| 能力 | 路线图优先级 | 状态 |
|------|-------------|------|
| 多租户隔离 | P2 | 未实现 |
| SSO / OAuth2 | P1（计划 v0.12.0） | 开发中 |

## 8. 总体结论与建议

### 8.1 总体评价

**Pantheon-Base 在企业级应用维度上表现优秀，已具备较高的生产就绪度**。亮点包括：

- **工程质量**：多层级 CI/CD、代码扫描、测试覆盖、发布门禁，达到一线互联网公司工程标准。
- **架构设计**：系统域与业务域解耦，为长期演进奠定坚实基础。
- **文档体系**：从部署到设计系统的完整文档，大幅降低企业采用和二次开发门槛。
- **安全与运维**：密钥管理、审计日志、可观测性等企业刚需均有覆盖。

### 8.2 使用建议

- **适用场景**：对多租户、SSO 无强需求的企业内部后台系统，且具备一定 K8s 运维能力来补充部署清单。
- **谨慎评估场景**：若需要多租户隔离、OAuth2/SSO 集成，建议等待 v0.12.0 或 V1.0 正式发布后再做决策。
- **投产准备**：当前版本可作为生产试点，但建议：
  - 补充 Kubernetes 生产清单
  - 完善性能基准测试
  - 根据业务需求评估低代码生成是否需要更动态的方案
