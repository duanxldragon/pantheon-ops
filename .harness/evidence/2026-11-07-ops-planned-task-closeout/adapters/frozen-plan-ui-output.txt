**Findings:**

**P2 — `confirm()` conflates `onStarted()` failure with start failure.** If `startDeployTask` succeeds but the awaited `onStarted()` rejects (its type is `Promise<void>`), the shared catch nulls `preview` and forces `stale`/`forbidden` — a false failure signal after a successful start. No double-start (confirm is disabled in non-ready states), but the user must refresh and re-preview. Minimal fix: put the `startDeployTask` call in its own try/catch that sets the failure state and returns; await `onStarted()` after it, with its own catch (so `void confirm()` can't yield an unhandled rejection).
