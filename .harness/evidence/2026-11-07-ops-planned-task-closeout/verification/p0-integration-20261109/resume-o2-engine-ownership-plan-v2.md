**Ownership and serialization.** Carry an execution-local token `(taskID, taskHostID, physicalHostID, attemptID, workerID, taskLeaseOwner)`. Under locks require the latest attempt by monotonic attempt number/ID, matching task/host/worker, `running`, nonnull unexpired attempt lease and exact live physical lease `TaskID/Owner = taskID/deployHostLeaseOwner(taskID)`. Never renew another task's lease. Claims, reconciliation, renewal and completion share the persisted task-host key and physical lease row, replacing process-local exclusion.

Every transaction needing sequence or final task state locks **task first**, then all task-host rows/current attempts, then physical host leases, then CMDB result rows through the existing transaction-bound capability; order each set by stable IDs. Lock checkpoint/history rows afterward. Pure renewal locks only task-host/current-attempt/physical-lease and never later task. `withTaskSequence` must establish task lock before invoking a fenced writer. Release checks and deletion stay in that transaction. Reserve missing task-host rows using existing unique `(task_id,host_id)`; materialize/lock physical leases using the existing unique `host_id` and atomic duplicate-safe insert followed by `FOR UPDATE`. Competing tasks cannot check then independently take a lease. Recovery acquires/reassigns physical leases only during admission/new-claim transactions excluding live prior claims; renewal never reacquires.

Existing start/preview/control paths sometimes lock CMDB before acquiring leases. Split nonlocking candidate discovery/ticket parsing from locked validation: task → reserve/lock task-hosts → physical leases → sorted capability CMDB locks → revalidate exact selection and commit. A changed footprint rolls back; reviewed starts require fresh preview, legacy starts retry bounded discovery. No lower-rank lock is acquired after CMDB. Use `WithTargetTransaction(tx)` (the existing WithTx facility), retaining the outer transaction through `WriteDeployHostResult`; prelock component snapshots through the bound host resolver. No global writer copy or CMDB implementation change.

**Dual renewal and stopping.** Renew attempt to five minutes and physical lease to thirty minutes atomically under the above fence every one minute, starting before execution and continuing through final projection/finish. Sample database `CURRENT_TIMESTAMP(6)` after locks; conditional mutations recheck database time: `<=` expired, `>` live. Claim, active checks and reconciliation use that same boundary, never application-supplied time. Null legacy leases cannot establish execution ownership; preserve their reporting history while reconciliation retires abandoned running claims under locks.

Each DB operation, including lock waits/commit, gets a five-second context deadline. First DB/read/ownership failure immediately cancels locally; no renewal resurrection or conversion into failure writes/requeue. Independent monotonic watchdog cannot wait behind DB I/O. After a confirmed claim/renewal, its deadline is the earlier of request-start monotonic time plus five minutes and response-receipt time plus DB-observed minimum lease remaining minus full query latency, minus ten seconds for precision/skew/scheduling. Late/failed replies never reset it. Check deadline before commands and writes; cancel on expiry. This conservatively limits execution to last confirmed ownership despite latency; arbitrary DB clock jumps/remote effects cannot yield stronger guarantees. Close SSH and join output/runner, renewal and watchdog on every return path.

**All effects.** Fence logs/events, checkpoint/history, trace, host results, component mutations, finish, release, requeue and final task state. A void `LogWriter` latches fence errors into the execution cancel cause. Finish/result/next-retry disposition commits together while ownership is running; older callbacks cannot overwrite recovered attempts. Final task recomputation rereads settled hosts/latest claims under task-first locks, within fenced finish or serialized reconciliation; post-finish callbacks cannot write using retired ownership. Retain three cumulative nonpaused attempts, free paused attempts, increasing history, crash recovery, pause/cancel, legacy reporting and existing timeouts. No new modes/tables/history reset. Arbitrary remote scripts may leave ambiguous effects; no exactly-once, rollback or remote-child termination promise.
