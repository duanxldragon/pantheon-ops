# O2 adjacent engine ownership repair proposal — independent ARCH required

Parent: `docs/harness/tasks/2026-11-07-ops-planned-task-closeout.task.md`; original O2: `.harness/tasks/2026-08-31-ops-operational-workbench-design/packets/O2-deployment-execution-workbench.md`.

Status: proposal only. CODE3 remains an open HIGH. No engine lease, recovery, execution mode, history reset or exactly-once implementation is authorized by this repair lane. Root routes this proposal to independent engine ARCH before implementation. The source hashes in `resume-o2-review-blockers-fix-hashes.json` bind the touchpoints below to the handoff source; prior v9 artifacts remain historical and unmodified.

The defect is fixed-five-minute attempt expiry versus supported thirty-minute/default and twenty-four-hour/max execution. Process-local `taskWorkers`, task-owned host leases and attempt completion by ID/worker alone do not exclude a second live process or fence the first process after recovery.

Minimum proposed implementation, confined to `backend/modules/business/deploy/deploy_service.go` and necessary deploy-local regressions:

1. Reuse `DeployTaskAttempt.ID`, `WorkerID`, `Status`, `LeaseExpiresAt` and `DeployTaskHost.ID`. Treat the acquired attempt ID plus worker ID as the ownership token. Avoid a new execution mode, table or attempt counter. `claimAttempt`, `ReconcileDeployAttempts`, `hasActiveTaskAttempt` and every renewal/fenced write serialize on the same host row before checking/updating the current running attempt. Task control retains its task-before-host lock order; attempt renewal must not acquire the task lock after acquiring the host lock. Specify one database-clock expiry comparison and boundary (`<=` versus `>`) consistently.
2. `runAsyncTaskHost` passes the token through `executeAsyncHostAttempt` to an execution-local service/provider/log writer (explicit ownership struct, no copied synchronization maps). Start a bounded renewal loop before remote execution and keep it active through checkpoint, final host projection and attempt completion. A candidate cadence is one minute against the existing five-minute lease, subject to ARCH. Conditional renewal requires that the claim is still running, current, same worker and unexpired; expired ownership cannot be resurrected. Temporary DB errors must cause cancellation early enough that execution cannot knowingly continue past the last confirmed lease. Stop and join renewal on every exit.
3. Check ownership before each command/probe via the existing `executionScopeSSHRunner` boundary, while retaining its current source/host validation. Lost ownership cancels the attempt context and closes the current SSH runner through existing `runDeployScript` cancellation; wait for local output copying/runner close before releasing local resources. Renewal protects long blocked commands, rather than only checking between commands. An execution deadline or hard-coded longer lease alone is insufficient.
4. Fence `updateTaskStepStatus` and `appendStepCheckpointHistory` in their existing transaction, plus `markHostResultWithSummary`/`finalizeTaskHostExecution`, `appendTaskHostTrace`, ownership-bound `WriteLog`/`appendLogChunk`, step/host events and CMDB component result mutations. The token must still name the current unexpired running claim under the same host row lock. A failed fence returns ownership-lost; it must not be converted into a failure checkpoint, a success result or an event by the old worker. Keep manual reporting semantics separate from execution-local writes, without weakening their existing CAS, DataScope or result replay rules. No durable unscoped writer should be used by async execution.
5. `finishAttemptWithStatus` conditionally finishes only current running ownership; never overwrite a claim already marked retryable/recovered or append duplicate result history. `releaseInactiveTaskHostLeases`/`releaseHostLease` must not release leases still protecting another live/current claim. `runAsyncTask` final cancellation/status recomputation must reread settled host/current claim facts and avoid an old worker deciding the new worker's result. Preserve the current three cumulative nonpaused attempts and strictly increasing attempt history.
6. Preserve crash recovery: a stopped process cannot renew, expired abandoned claims become retryable, and the next process claims a new attempt under the same host lock. Reconciliation races with renewal/finish must have a single serialized winner. Recovery does not reset checkpoints, reconstruct old attempts, bypass admission or silently widen credential/session scope. Keep pause/resume and cancel semantics, request transaction dispatch timing and supported execution timeout limits.

Regression requirements before approval:

- Two service instances share isolated real MySQL and a blocked executor. Inject/control the lease clock/cadence locally in tests; do not sleep five minutes. While service A remains live beyond the original lease horizon, assert renewed ownership and that service B reconciliation/claim does not execute. Release A and assert one committed current result/history.
- Force A's ownership to be lost, observe cancellation/runner closure, let B obtain a new claim, then release a deliberately delayed old executor callback. Assert A cannot update checkpoint/history, logs/events, host result, component projection, attempt status or B's lease. This specifically tests stale writers that ignore cancellation.
- Stop renewal to represent process crash; expired A is recoverable by B; preserved successful checkpoints are skipped; nonpaused budget and monotonically increasing attempts remain unchanged. Test renewal-versus-reconcile and completion-versus-reconcile races, timeout, pause, cancellation, database failure and full cleanup.
- Retain the existing real SSH cold-restart and long-command timeout acceptance. A local blocked fake proves ownership scheduling/fencing only; root must run the real transport acceptance afterward.

Remote side-effect boundary: losing/closing local SSH ownership does not prove the remote command or its spawned children stopped or that an effect was rolled back. A crash can leave an ambiguous remote outcome. Existing fixed-component health probes can help reconcile their supported operations; arbitrary scripts can rerun under the current contract and remain unsafe to describe as exactly-once. Report the ambiguity explicitly; do not invent inverse scripts, reset history, claim cancellation reverses side effects or introduce new automated replay guarantees without a separate authorized contract decision.

ARCH decision required: renewal cadence/failure deadline, the exact ownership lock order across task/host/attempt and all CMDB result writes, and whether the preserved automatic crash replay contract is acceptable for ambiguous script outcomes. Implementation begins only after root's independent design routing; the current log/SSE/budget/UI handoff does not close CODE3 or O2/P0.
