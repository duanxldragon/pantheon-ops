## Source-contained behavior

- Application PUT authorizes current and proposed effective source/destination/namespace with the registered owning server/cluster. A shared DTO mapper retains omitted/empty strings; fields outside the update DTO cannot change server/cluster. The service repeats authorization inside the row-locked write transaction. Denial leaves DB unchanged and provider count zero. The allowed-path MySQL test additionally found the existing source column typo: model `DestinationNS` maps to `destination_ns`, not `destination_namespace`; the mapper now uses the existing model column. No SQL/schema edit was made.
- One explicit Group/Kind allowlist governs destination namespace defaulting and mutation permission. A custom group cannot borrow standard `Role`, `Deployment` or `Service` semantics. No discovery framework or permissive fallback was added.
- Review fingerprints contain authoritative app execution configuration/identity, server endpoint/cluster/credential/CA/version, and repository identity/configuration/credentials. Poll status, `LastChecked`, sync/health/error and timestamps are excluded. Registration availability is separately rechecked, including at reservation and dispatch; disconnection/deletion is not silently enabled by excluding status. Provider UID/resourceVersion/spec conditional PATCH remains mandatory for a new action.
- Collection query/cancellation/authority infrastructure errors safely fail the whole request; only typed Forbidden/NotFound and genuine GORM record-not-found may filter individual resources. Authority callbacks must use public typed sentinel errors for proven policy decisions. Unclassified callback errors become sanitized internal failures, with only error type logged. Handler-local audit masking still applies only when the handler executes.
- Reservation metadata keeps the original action nonce/UID/revision, actor ID, SHA-256 of the exact encrypted ticket and original source/target references. Resubmitting the same ticket/revision/action first finds that actor's exact record, including outside the public latest-50 window, then checks current and originally reviewed resources. It returns Unknown/Running/terminal as persisted, even after ticket expiry or provider/config/credential drift. It never dispatches. Foreign actor, current actor/source/target revocation, changed requested target, malformed ticket or missing authority deny. An app-row-locked correlation recheck closes simultaneous same-ticket submissions. Reconciler terminal correlation and legacy unresolved-action blocking remain intact.

2. On confirmation, POST the matching `/sync` or `/rollback` with `{revision: preview.targetVersion, intentVersion: preview.intentVersion}`. Do not create a fresh preview/action just because the result is Unknown. Poll the same reviewed submission for its exact result; the generic latest-50 history is not an exact recovery API.
4. For a new unexecuted action, 409 means invalid/expired/stale review or another unresolved action. Refresh current state, require a fresh preview and confirmation where a new action is permitted, and retain the unresolved-action block. A changed target must not reuse an old ticket. Validate unauthorized/403, translated safe failures, 409 refresh and uncertain/terminal states with rendered UI evidence before enabling this flow.
