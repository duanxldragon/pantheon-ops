## Minimum plan and implementation

Reuse current CMDB reader, task membership, task command transaction, append-only history, RequestError and existing Arco controls. Add only a deploy-local current-read boundary and a task snapshot hook; no shared/Base/CMDB/BizScope implementation, dependencies, execution modes, filesystem locks, governance ledgers, commits, release, remote operations or credential-config reads.

- `read_scope.go`, `deploy_handler.go`, `deploy_service.go`: intersect CMDB visibility with actual persisted task hosts before log sorting, 500-row cap, cursor and first-error selection. Public log reads also correlate nonlegacy step ownership. Explicit hidden/foreign/mismatched host or step selections consistently project to empty, preserving detail projection semantics and task visibility before query validation.
- REST events and every SSE batch use current scoped reads, correlate host/step ownership and retain a finite 500-event sequence page. Partial visibility removes unscoped task aggregate reason strings, including embedded nested host data. Whole visibility loss writes `event: forbidden` with an empty payload and ends the stream. No hidden-host IDs/output are sent in the tested partial/revoked paths. No new live IAM/session reconstruction is claimed.
- Public `RetryTask` now locks the task and transacts admission, host state, task state and command event. Version-bound ControlTask uses the same admission. SSH retry checks cumulative nonpaused attempts under host locks before any writes; exact three chargeable attempts return existing key `business.deploy.attempt.exhausted`, publicly mapped to conflict/409. Paused attempts remain free; monotonically increasing history is preserved. Manual execution retains its existing no-worker/no-attempt semantics.
- `useDeployTaskSnapshot.ts`, `useDeployTaskStream.ts`, `DeployTaskDetail.tsx`: silent detail denial or explicit stream denial clears task state and unmounts workbench/frozen log snapshots; selected result/preview/credential copies clear on lost access. Departed request/stream generations cannot clear a new task. In-flight refreshes coalesce; a denied generation fences old successful replies. Ordinary refresh failure retains content, visibly marks stale, and enables the existing recoverable five-second polling even while SSE remains connected.
- Cancel exposes paused/pause_requested, plus the backend-supported manual cancel_requested continuation, with existing permission, confirmation and viewed-version behavior. Completed/failed tasks expose the existing server-authorized rollback draft route under rollback permission and confirmation; successful creation navigates to the existing edit/draft route. Unsupported inverse capability remains server-rejected. No new inverse script/DAG behavior.
- `DeployExecutionWorkbench.tsx`: select the actual failed current checkpoint first, then its own step ID/attempt. When successful current steps have unequal counters, the default is all attempts/current checkpoints rather than a fabricated host-wide maximum. Explicit attempt/deep-link selection remains supported.
- `deploy_seed.go` and deploy-local en-US/zh-CN JSON supply four new messages (exhausted, rollback draft/confirmation, refresh stale). Generated runtime fallback resources were deliberately not edited; root must materialize/rebuild the business locale projection and seed the acceptance runtime. The existing `business.deploy.attempt.exhausted` key is reused; root owns any canonical appendix/derived-resource reconciliation outside this lane.
- Narrow native TS repairs: explicitly widen cursor hook initialProps; add optional `TaskRow.remark` in the named smoke fixture.
