# O2 engine ownership proposal v3 — component read consistency

L2 parent: `2026-11-07-ops-planned-task-closeout`. This supplement inherits the exact v2 ownership, dual-lease, lock order, DB-time boundary, deadline/watchdog, write fencing and test protocols. Proposal only. V2 and both independent review reports remain immutable. No engine implementation or P0 closure is asserted.

The independent CODE review identified a concrete MySQL REPEATABLE READ gap: a prior plain read can establish an old transaction snapshot, and locking the CMDB host afterward does not refresh `loadInstalledComponents`. ARCH-v2 readiness is superseded until this correction receives independent review.

Any deploy transaction that can project host/component results must BEGIN with `database/sql.TxOptions{Isolation: sql.LevelReadCommitted}` before its first read. This includes fenced finish/result projection and any existing legacy/manual result path covered by the change. Nested GORM transactions reuse that outer transaction and cannot establish or change its isolation. An already-open transaction with unknown or REPEATABLE READ isolation must not be treated as a compliant projection transaction. Keep task-first ordering, physical ownership fences and the existing transaction-bound CMDB capability. Do not change the shared CMDB implementation or silently move the projection to an independent transaction.

Once the CMDB host is locked through the bound capability, READ COMMITTED permits the component query to observe updates committed before that query. The host lock continues to serialize writers that obey the existing capability contract. This does not claim correctness for out-of-contract direct component writes. Use one deploy-local transaction entry/helper where it avoids duplicate isolation configuration; do not add a platform abstraction or dependency.

Add a required real-MySQL deterministic barrier regression: transaction A begins the final projection protocol and performs a plain read; transaction B updates the host's installed-component JSON through the existing CMDB capability and commits; A then locks the host and invokes the bound result writer. Assert B's component remains along with A's intended change. The pre-repair REPEATABLE READ implementation must fail this assertion, and the READ COMMITTED implementation must pass. Also verify the projection entry points actually select this isolation at the outer transaction and preserve rollback, stale-ownership refusal, task/host lock order and retained history.

Implementation remains restricted to the deploy module and meaningful regression tests. Independent CODE and ARCH must confirm this supplement closes the sole v2 plan HIGH before the owning Generator changes engine source. Full proposed engine concurrency, dual renewal, blocked DB/watchdog, stale callback, crash/recovery and current-source VM acceptance remain unexecuted gates.
